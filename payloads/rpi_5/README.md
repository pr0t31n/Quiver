# Raspberry Pi 5 — Provisioning Payloads

The Raspberry Pi 5 (16GB) is a full ARM64 single-board computer, not a microcontroller — there is no UF2/BOOTSEL flow. Quiver provisions it exactly like the Pi 4B module with two firmware payloads. **OS Image** (`image-os.qfw`) writes a bootable OS — Raspberry Pi OS 64-bit (auto-downloaded and SHA-256 verified), Kali Linux ARM64 (operator-supplied URL), or a local `.img`/`.img.xz`/`.img.gz` — to a removable SD/USB/NVMe target using `rpi-imager --cli` (with a `dd` fallback); a device-safety guard enumerates only removable/external disks, refuses the host's system disk, and re-checks immediately before the write. **Bootloader EEPROM** (`update-eeprom.qfw`) stages the latest SPI-EEPROM bootloader via `rpi-eeprom-update -a` (applied on next reboot) and only runs when the module is executing on the Pi 5 itself. Each payload auto-runs with a single confirmation: device info → prepare (download/verify/target-select) → summary → "Are you sure?" → flash.
